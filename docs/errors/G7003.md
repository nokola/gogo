# G7003 — a file's root announces what it is: `View` or `Panel`

The file's root node is neither `View` nor `Panel`. The root keyword set is
exactly those two — a file announces itself as a SCREEN or a COMPONENT in
its first word.

## Why

The root IS the host control (WPF-UserControl-style), and there are two
kinds of file worth being:

- **`View` — a screen**: fills the host, children place FREELY
  (`halign`/`valign` + margins, no wrapper), transparent to paint and input
  unless the file says otherwise, `View background=...` draws the root
  plate. Host classes extend `Control` (`GogoView`).
- **`Panel` — a component**: the root IS the styled box — a toast banner, a
  progress track. Container regime for its children, native padding/border
  stacking, no wrapper node; the host is the widget itself, embedded
  anywhere. Host classes extend `PanelContainer` (`GogoPanelView`).

One keyword per concept, both announced by the file's first word — a reader
never has to ask "screen or box?".

## Wrong

```gogo
// menu.gogo — a Column root announces neither
Column menu halign=center { ... }
```

## Fix

A screen wraps its content in `View`:

```gogo
View menuScreen {
    Column menu halign=center, valign=center { ... }
}
```

A self-contained box keeps its own `Panel` root:

```gogo
Panel toastPlate background=#000000FF, padding=12, valign=top {
    Label tipText text=""
}
```

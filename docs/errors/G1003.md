# G1003 — areas-form rules: rectangles, one name per child, tracks per line

An `areas=` Grid broke one of the naming rules:

```
Grid cols=[hug, fill],
     areas="header header : 60
            nav    body" {
    Panel header { ... }
    Column sidebar { ... }     // error[G1003] — no area named 'sidebar'
}
```

## Why this is an error

The areas string is a PICTURE of the layout (CSS grid-template-areas): each
line is a row, each token a column track, `.` an empty region, and an
optional `: height` suffix carries the row height WITH its row (no separate
`rows=` list to desync). The picture only works if it stays coherent:

- **Every line spells one token per column** — a line with more or fewer
  tracks than `cols=` declares is a miscount, same as row-form arity.
- **An area is one contiguous rectangle** — a name scattered in an L-shape
  or two islands has no single rect to place a child in. A split shape is
  two areas with two names.
- **Children bind by node name** — a nameless child has nothing to bind to;
  a name matching no area is a typo (the error suggests the declared ones);
  an area bound twice has two children fighting for one rect. An area with
  NO child is only a warning — sketching the layout first is fine.

## Fix

- Line width: add/remove tokens (or `.` holes) until each line matches
  `cols=`.
- Shape: give each rectangular piece its own name.
- Binding: name the child after its area (`Panel header ...`), fix the
  typo, or remove the duplicate.

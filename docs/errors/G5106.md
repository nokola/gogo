# G5106 — contract features need the Gogo backend

A NATIVE built-in instance (a `Slider` drawn by Godot's HSlider, a plain
`Button`) is being asked for something only its Gogo composite can do:

- wearing a `for=Slider` style (slot paths address composite slots),
- an inline `slot.` prop (`Slider s slot.thumb.size=10`),
- a `slot <name> { }` fill (native nodes have no slots to fill),
- a plain style responding to a contract state only the composite raises
  (the native backend runs no behavior to flip it; `held` is NOT this
  case — the grabber's drag raises it on both backends, D181),
- a theme entry pairing a `for=X` default style without `render=gogo`
  (this shape fires ONCE, at the entry, instead of at every instance).

Native instances render through Godot's theme pipeline; slots, automatic
geometry and composite-raised states exist on the Gogo-drawn version of
the control (spec §5.7).

## The fixes, cheapest first

1. **Drop the `for=`** — offered when nothing in the style needs the
   contract (no slot paths, only states the native node raises). The style
   then applies natively, today, with no backend change.
2. **Opt the instance in: `render=gogo`** — swaps in gogo's composite
   implementation. It looks the same until you style it (the composite
   draws the same theme resources) and behaves identically (conformance-
   tested against the native node). The stated cost: the node's CLASS
   changes, so `as HSlider` casts on that instance stop working — address
   it through `value` / states / signals, which both backends speak. The
   fix-it is confirm-level: shown, never auto-applied.
3. **Make it app policy** — a theme type entry flips every instance at
   once: `theme { Slider .ThinSlider render=gogo }`; individual instances
   opt back out with `render=native` (which discards the entry whole).

In practice this error is **Slider's** — the one control with two
backends. **Toggle never fires it** (D113): it is Gogo-implemented always,
so every instance already has the contract behind it. **Button never
fires it either** (D112): its contract has no slots, so a `for=Button`
style is pure write-time state checking and applies natively; slot paths
and fills on a Button get a terminal error instead — content is free-form
children, and named fill points are a widget's job
(`widget IconButton { Button { Row { slot leading; slot } } }`).

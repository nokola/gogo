# G8001 — translation key already carries different English text

A `"literal"/key` value registered a key whose literal disagrees with what
the same key says somewhere else:

```
Label a text="save"/save
Label b text="Save it"/save     // error[G8001]
```

## Why this is an error

The literal next to a key is the ENGLISH SOURCE TEXT — the one string the
key stands for, and the fallback every locale without a table shows. Two
different literals under one key means one of them silently isn't what the
translators translated ("edited one spelling, forgot the other" — the exact
drift bug the fused `/key` spelling exists to prevent). The secondary span
points at the first registration, which may live in another file.

## Fix

- Same term, same text: make the literals identical — repeating a key with
  the SAME literal is legal and is how views share a string.
- Actually different text: give the new text its own key.
- You meant to reword the term: change every literal that carries the key
  (the error lists where the other one lives).

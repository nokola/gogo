# G9003 — `by` must key the item binding

The key path starts at the loop binding and walks fields — nothing else can
parse (no calls, no operators, no literals: unstable keys are
unrepresentable, not linted).

```gogo
repeat tasks by $item.id { ... }            // field of the item
repeat tasks by $item.meta.uuid { ... }     // nested fields are fine
repeat names by $item { ... }               // the item is its own key
repeat tasks as $task by $task.id { ... }   // renamed binding, same rule
```

Rejected shapes this code reports:

- `by $other.id` where the binding is `$item` (or the `as`-declared name) —
  the key must come from the item being repeated.
- `by $item` misspelled against a renamed binding (`as $task by $item.id`).

## Notes

- Key VALUES must be String or int, checked at assignment (gogo binds
  GDScript data — there is no compile-time schema). Wrong-type, missing and
  duplicate keys refuse the whole assignment: G9102/G9103.

# G4001 — layout geometry driven by an anim

An anim tried to drive `width`, `height`, offsets, `position`, `size` or
another property the layout engine owns.

## Why this is an error

gogo's animation law is **one writer per property**. Layout geometry
already has a writer: containers re-place children on every relayout, epx
bindings re-apply on `units_changed`, and hot reload re-asserts the
declared pose. An anim's value would be stomped mid-flight — sometimes
visibly, sometimes only on rotate, always eventually.

## Exits

- **Transient pulse** (bounce, pop, shake): animate the motion words
  instead — `scale.x` / `scale.y` / `translate.x` / `translate.y` /
  `rotate` / `opacity`. They use a separate offset transform that gogo
  arms only while motion is live, so the layout never fights it.
- **Change and stay** (a drawer opening, a panel growing): that's not a
  flourish, it's a new standing truth — declare an `arrangement`, respond
  with `when <name> { node.prop=... }`, and time the flip with
  `transition base -> <name> duration=...`.

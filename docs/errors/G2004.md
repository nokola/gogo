# G2004 — invisible pigment: alpha 00 under color channels

A static `background=` / `border_color=` value has alpha `00` while its
color channels are non-zero — a pigment that can never paint, spelled as
if it were a color.

## Why this is an error

gogo hex is `#RRGGBBAA` — alpha LAST (the Godot/CSS order). WPF/XAML hex
is `#AARRGGBB` — alpha FIRST. A XAML literal copied verbatim parses as a
structured color at alpha zero and silently vanishes: `#77000000` (a 47%
black smoke in XAML) reads here as dark red, fully transparent. Nothing
paints, everything drawn over the missing fill loses its contrast, and no
tree-level check can see it — the declared value matches the file; only
rendered pixels disagree. gogo refuses the line rather than paint nothing.

The error's note spells the alpha-moved literal, so a genuine XAML port is
a copy-paste fix.

## Fix

- Porting a XAML color: move the leading alpha pair to the end —
  xaml `#AARRGGBB` -> gogo `#RRGGBBAA` (so `#77000000` -> `#00000077`).
- Deliberate transparency: `background=#00000000` (the canonical
  transparent spelling), or hide the node with `opacity=0` /
  `visibility=`.

## Not covered on purpose

Gradient `stops=[...]` keep alpha-0 endpoints (`#FFFFFF00` fade-outs are
values of the gradient, not a node's pigment), and `when`/`anim` color
endpoints stay free — a tween may legitimately pass through alpha 0.

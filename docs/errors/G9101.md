# G9101 — items assignment refused: the collection itself

`Gogo.set_items` hands a repeat its WHOLE collection; assignment is the
change event. This refusal family covers the collection being unusable
before keys are even read:

- **`null`** — pass `[]` to clear a list (the `empty` block shows). `null`
  is refused because it usually means an uninitialized variable, not an
  intentional empty list.
- **not an Array** — dictionaries, single items and strings don't iterate
  in a defined order.
- **the item template failed** — a template error that needs data to
  surface (an unknown style, a field of the wrong type for its property)
  reports here on first assignment, with the full underlying diagnostic.

## The refusal doctrine

A refused assignment changes NOTHING: the previous items stay live, whole.
Gogo never half-applies a list and never halts shipped software — the loud
refusal (full block on the Output panel) is the mechanism that makes the
bug impossible to miss in dev and CI. This is the shipped "last good tree
stays live" philosophy applied to data.

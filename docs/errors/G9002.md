# G9002 — repeat clauses: `as` declares, `by` is required

A repeat line is `repeat <name> [as $binding] by <key-path> { ... }`.
Clauses are keyword-anchored and comma-free (the keyword is the delimiter,
like a transition's `->` endpoints).

```gogo
repeat tasks by $item.id { ... }                 // default binding: $item
repeat tasks as $task by $task.id { ... }        // renamed binding
repeat themeNames by $item { ... }               // primitives: the item IS its key
```

This code covers:

- **missing `by`** — the identity key is mandatory. Keys are why reorder,
  insert and remove keep per-item state (focus, states, selection later)
  attached to the RIGHT items. There is no index fallback, ever — index
  identity silently misattaches state.
- **malformed `as`** — the binding declares with its sigil, like every other
  `$` introduction (`$param=default`, `$name = value`): `as $task`, no dots.

## Notes

- Omitted `as` is defined sugar for `as $item` — and because `by` must name
  the binding, every repeat line displays its item variable at least once.
- `as` comes before `by`: introduce the binding, then use it (parse error
  otherwise).

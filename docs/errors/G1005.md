# G1005 — a seated hug occupant's wrap-text is wider than the window (lint)

A seat's socket hugs its occupant, and a HUG occupant measures wrap-text
at its UNWRAPPED, full single-line extent (one meaning for hug, D254). When
that single-line width is wider than the window, the socket can never
report less, every box around it inflates to honor the minimum, and the
layout renders pushed off-screen — with no error anywhere, because every
individual rule behaved correctly. This lint names that state at the
moment the occupant arrives. Advisory: the tree is legal.

```gogo
Row strip {
    seat infoSeat                        // the socket, inside a half-screen pane
}
Column home {
    Panel blurb {                        // hug-sized (no width declared)
        Label text="a long explanation that should wrap inside the pane",
            autowrap_mode=word_smart
    }
}
when screen.landscapeSmall { blurb.seat = infoSeat }
// warning[G1005]: seat 'infoSeat' occupant 'blurb' measures 1240 px wide
// on one line — wider than the window (720 px).
```

The fix is one line — declare the occupant's width intent:

- `width=fill` on the occupant — its wrap-text measures WRAPPED (fill asks
  the socket for size; there is no hug to honor), so the seat fits its
  pane and the text folds there (D263).
- An exact `width=N` — the number IS the box, and the text wraps at it.

The lint stands down where wide-is-fine: occupants whose width already
binds wrap (`fill` / exact — the trap can't form), and seats under a
horizontally scrolling `Scroll` (wide content is that axis' purpose).
It also only fires when wrap-text is what inflated the occupant (the
unwrapped measure well above the wrapped one) — a genuinely wide image
or a declared `min_width` is your stated intent, not a trap.

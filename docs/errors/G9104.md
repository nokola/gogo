# G9104 — a List `selected` write refused

The repeat refusal doctrine (G9101–G9103) at the `selected` surface:
an invalid write changes NOTHING — the last good selection stays live,
the refusal prints loudly, shipped software never crashes over it.

Refused writes:

- **wrong shape for the mode** — `select=one` takes a single key
  (String or int) or `null`; `select=many` takes an Array of keys
  (`[]` clears).
- **duplicate key** in a `many` array.
- **any write under `select=off`** — there is no selection to write;
  activation still fires (`on:activate=` / `On<Name>Activate`).

```gdscript
picker.selected = "t2"          # one: ok
picker.selected = null          # one: cleared
tags.selected = ["a", "b"]      # many: ok
tags.selected = ["a", "a"]      # refused — duplicate key
```

Keys that name no present item are NOT errors — they are **inert**: they
render nothing and read back until reassigned or the item arrives, so
select-then-load needs no author code. Read-back order under `many`:
present keys in collection order, then inert keys in the order they
entered the selection.

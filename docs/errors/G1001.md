# G1001 — grid cells place by structure or by name, never coordinates

A Grid child sat outside the placement form the Grid uses:

```
Grid cols=[hug, fill] {
    Label lbl text="Size"      // error[G1001] — not inside a row { }
}
```

## Why this is an error

Gogo grids have no `grid.row=1` coordinates on purpose: index placement is
the WPF failure mode (insert a row, renumber every child; read a grid,
mentally JOIN two tables). Instead a Grid uses exactly ONE of two forms:

- **row form** — placement IS structure. Cells live inside `row { }`
  blocks, walked left to right against the `cols=` signature. Moving a UI
  row is cut/pasting one block; nothing renumbers.
- **areas form** — placement by NAME. The `areas=` string is a picture of
  the layout; children bind to areas by node name.

Mixing the two in one Grid is also this error: two placement systems in one
container is two answers to "where does this cell go" (the same reason an
anim is either flat or structured, and a Rust struct is tuple OR named).

## Fix

- Row form: wrap the cell in a row block — `row { Label lbl ... }`.
- Areas form: give the Grid an `areas=` string and NAME the child after its
  area.
- `Row` (capital — the stack control) can be a CELL; the lowercase `row` is
  the structural block. The case is the register, as everywhere in gogo.

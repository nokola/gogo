# G9015 — this List provably gets no height here (lint)

A viewport List's minimum is near zero (rows never size the box — the
viewport doctrine, D121; fixed content like headers does, D127). A
hug-sized parent grants children their MINIMUMS, so the chain below
provably starves the rows — and gogo says so at build time, where the
no-data editor preview would otherwise show nothing silently. Advisory:
the build still succeeds.

Two provable shapes:

```gogo
Column menu valign=center {            // valign= anchors it: hug-sized
    Button newGame text="New Game"
    List picker {                      // warning: gets no height here
        empty { Label text="none" }
        repeat tasks by $item.id {
            ListItem { Label text=$item.title }
        }
    }
}
```

```gogo
Scroll {
    Column {
        List picker {                  // warning: the page's axis is
            repeat tasks by $item.id { // unbounded, and the List scrolls
                empty { }              // ITSELF (two pans would also fight)
                ListItem { Label text=$item.title }
            }
        }
    }
}
```

Fixes, pick one:

- `height=<epx>` — pin the viewport.
- `height=hug` — size to the items (add `max_height=` to scroll past a
  cap: the centered-menu arc).
- Put the List in a slot that fills (a sized Column, a fill track).

The walk is conservative — only Column chains prove starvation; `Row`,
`Layers`, `Grid`, `Panel` and widget seams stay quiet, and the runtime
half-starved nudge covers what build time can't see.

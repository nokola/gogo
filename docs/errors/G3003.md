# G3003 — `seat` and `transition` cannot apply to the same arrangement

A `when <arrangement>` block moves a node into a seat, but a `transition`
rule asks changes involving that arrangement to animate. Both cannot hold:
a seat move re-parents the node, and a node is in one parent or the other —
there is no "40% re-parented" for an animation to show.

The rule underneath: a `when` may carry a seat move only when its change is
**instant** — screen whens and composed `when <arrangement> screen.<class>`
blocks always qualify, and a plain arrangement `when` qualifies exactly
while no `transition` rule can time that arrangement (no rule naming it, no
bare rule, no `any` endpoint).

The error shows both places — the seat move (primary caret) and the
transition rule that times the arrangement (secondary underline) — because
the two lines can be far apart and written months apart, and whichever one
was added LAST is the one its author will look for.

## Wrong

```gogo
arrangement previewAbove
transition base -> previewAbove duration=0.3   // asks the change to animate...

when previewAbove {
    panelBrushPreview.seat = previewAboveSeat  // ...but this re-parents. Conflict.
}
```

## Fix — keep exactly one of the two

Drop the transition rule (the arrangement then changes instantly, and the
seat move is legal):

```gogo
arrangement previewAbove

when previewAbove {
    panelBrushPreview.seat = previewAboveSeat
}
```

or keep the animation and move the node with margins instead of a seat
(margins can animate; a re-parent cannot):

```gogo
arrangement previewAbove
transition base -> previewAbove duration=0.3

when previewAbove {
    previewHome.margin_top = -296
}
```

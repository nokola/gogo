# G3005 — one target posed from both screen vocabularies

The screen has two independent truths: a size **class**
(`screen.portraitSmall` … `screen.lotsOfSpace` — how much room there is)
and an **orientation** (`screen.portrait` / `screen.landscape` — which way
it runs). One of each holds at the same time: a sideways tablet is
`landscape` AND `lotsOfSpace` at once.

So when one target takes a pose from a class `when` AND from an
orientation `when`, both blocks are active together on every screen and
only one pose can win. The general rule would settle it by file order
(equal count → the later line wins), but here that would decide an
always-on contest silently, when the language has a clearer way to say
what you mean. Gogo refuses the mix and asks you to say it.

```gogo
when screen.landscape    { info.opacity = 0.5 }   // error[G3005]: both of
when screen.lotsOfSpace  { info.opacity = 1.0 }   // these can hold at once
Rectangle info ...
```

The refusal covers, per target:

- a **style prop** set from both vocabularies,
- a node **placed** (width/height/margins/alignment) from both — the whole
  node, not just one key: placement poses land in one variant per node, so
  a width from `screen.landscape` and a height from `screen.lotsOfSpace`
  could not both apply either,
- a **seat move** (`x.seat = …`) claimed from both — a node sits in one
  seat.

Fixes, pick one:

- **Pick one vocabulary** for that target. Ask which truth the design
  actually keys on: "is it sideways?" → orientation; "is there room for
  the wide layout?" → a class.
- **Say the intersection** with the composed spelling — one condition,
  no contest:

```gogo
when screen.landscape screen.lotsOfSpace { info.opacity = 0.5 }
```

Arrangements are exempt: an arrangement is a user pose, not a screen
fact, and its contests with screen poses follow the placement rule — more
conditions win (a composed pair over a single), equal count → the later
line in the file wins.

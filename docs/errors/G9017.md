# G9017 — `layout` picks a List's items panel

`layout <Panel> { repeat ... }` chooses how a List arranges its rows — a
CLOSED set, each owning its scroll axis and cursor navigation:

| panel | rows | scrolls | arrows |
|---|---|---|---|
| `Column` | top-to-bottom (the default — no block needed) | vertically | up/down |
| `Row` | left-to-right (a strip) | horizontally | left/right |
| `Flow` | wrap to the next line | vertically | geometric (2D) |
| `Tiles` | unit-lattice mosaic (`cols=`) | vertically | geometric (2D) |

```gogo
List gallery select=one {
    Label text="Swatches"
    empty { Label text="no swatches" }
    layout Flow spacing=8 {
        repeat swatches by $item.id {
            ListItem { Rectangle 40x40, color=$item.color }
        }
    }
}
```

The block holds exactly the List's one `repeat` — statics and `empty` sit
on the List body, beside it. One `layout` per List. The set is closed on
purpose: every List feature (hug, `max_height=`/`max_width=` caps, the
starve diagnostics, future virtualization) is specified against these four
modes; `Grid` is excluded (dynamic rows vs authored tracks is
underdefined), and anything else errors with this card.

Under `layout Row` the content-following words transpose: `width=hug`
(+ optional `max_width=`) — the strip's cross axis is content-sized by
nature.

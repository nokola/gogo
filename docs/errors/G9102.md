# G9102 — items assignment refused: a key

Every item must produce a usable identity through the repeat's `by` path.
Gogo binds GDScript data — there is no compile-time schema — so keys check
at assignment, and any failure refuses the WHOLE assignment (the previous
items stay live; see G9101 for the doctrine).

The cases:

- **missing field** — an item without the `by` field/property. The
  diagnostic shows the item and the path.
- **wrong type** — keys are String or int only. Floats above all (precision,
  NaN) are refused with no escape hatch; bools and structures too.
- **mixed types** — one collection keying some items by int and some by
  String would make `1` and `"1"` distinct-but-confusable identities.
- **field access through a primitive** — `by $item.id` walking into a
  String/number (the collection probably wanted bare `by $item`).

## Notes

- Item-as-key (`by $item`) is legal for primitive collections the author
  can guarantee distinct; user-entered or external data should be
  ID-bearing records — wrapping primitives in a record with an `id` field
  is the supported pattern.

# G1002 — grid track bookkeeping: arity, spans, and the `skip` they owe

The cells in a row don't add up against the Grid's track signature:

```
Grid cols=[hug, fill] {                  // 2 tracks declared
    row { Label a; Slider b; Label c }   // error[G1002] — 3 covered
}
```

## Why this is an error

`cols=` is the Grid's signature, and every `row { }` is arity-checked
against it the way a call is checked against a fn signature — that check is
what lets placement live in structure with no coordinates. Three shapes of
miscount all land here:

- **Too many tracks**: the row's cells (each `col_span` counting its full
  width) cover more tracks than `cols=` declares. Too FEW is fine — a row
  may end early; trailing tracks are empty and nothing shifts.
- **A missing `skip` under a row_span**: a cell with `row_span=N` OWNS the
  covered tracks in the next rows. Each covered track is spelled `skip`
  there, so the occupancy stays visible where it applies — gogo enforces
  the bookkeeping instead of silently flowing cells around invisible
  occupants (CSS auto-placement's spooky half).
- **A span past the edge**: `col_span` reaching past the last column, or
  `row_span` past the last row. WPF silently clamps these; gogo treats a
  span that doesn't fit as a miscount.

## Fix

- Arity: drop a cell, shrink a span, or add the track to `cols=`.
- Under a row_span: write `skip` for each covered track (the secondary span
  in the error points at the spanning cell).
- Past the edge: shrink the span, or add the rows/tracks it expects.
- An interior hole you MEANT: that's also `skip` — one per empty track.
